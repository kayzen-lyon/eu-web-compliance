## Criterion 12.1

**Official title:** Chaque [ensemble de pages](glossary.md#ensemble-de-pages) dispose-t-il de deux [systèmes de navigation](glossary.md#systeme-de-navigation) différents, au moins (hors cas particuliers) ?

### Tests

- **12.1.1** Chaque [ensemble de pages](glossary.md#ensemble-de-pages) vérifie-t-il une de ces conditions (hors cas particuliers) ?
  - Un [menu de navigation](glossary.md#menu-et-barre-de-navigation) et un [plan du site](glossary.md#page-plan-du-site) sont présents ;
  - Un [menu de navigation](glossary.md#menu-et-barre-de-navigation) et un [moteur de recherche](glossary.md#moteur-de-recherche-interne-a-un-site-web) sont présents ;
  - Un [moteur de recherche](glossary.md#moteur-de-recherche-interne-a-un-site-web) et un [plan du site](glossary.md#page-plan-du-site) sont présents.

### Special cases (cas particuliers)

Il existe une gestion de cas particulier lorsque le site web est constitué d’une seule page ou d’un nombre très limité de pages (cf. note). Dans ce cas-là, le critère est non applicable.

Le critère est également non applicable pour les pages d’un ensemble de pages qui sont le résultat ou une partie d’un processus (un processus de paiement ou de prise de commande, par exemple).

Note : l’appréciation d’un nombre très limité de pages devrait être réservé à un site dont l’ensemble des pages sont atteignables depuis la page d’accueil.

### WCAG references listed by the official file

- **Success criteria:** 2.4.5 Multiple Ways (AA)
- **Techniques:** G63, G64, G161

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `human-judgement`
- **Remains for a person:** Check across the set of pages that two systems are present among the menu, the site map and the search engine.

## Criterion 12.2

**Official title:** Dans chaque [ensemble de pages](glossary.md#ensemble-de-pages), le [menu et les barres de navigation](glossary.md#menu-et-barre-de-navigation) sont-ils toujours à la même place (hors cas particuliers) ?

### Tests

- **12.2.1** Dans chaque [ensemble de pages](glossary.md#ensemble-de-pages), chaque page disposant d’un [menu et les barres de navigation](glossary.md#menu-et-barre-de-navigation) vérifie-t-elle ces conditions (hors cas particuliers) ?
  - Le [menu et les barres de navigation](glossary.md#menu-et-barre-de-navigation) sont toujours à la même place dans la présentation ;
  - Le [menu et les barres de navigation](glossary.md#menu-et-barre-de-navigation) se présentent toujours dans le même ordre relatif dans le code source.

### Special cases (cas particuliers)

Il existe une gestion de cas particuliers lorsque :

- La page est la page d’accueil ;
- Le site web est constitué d’une seule page ;
- Le changement fait suite à une modification initiée par l’utilisateur.

Dans ces situations, le critère est non applicable.

### WCAG references listed by the official file

- **Success criteria:** 3.2.3 Consistent Navigation (AA)
- **Techniques:** G61, F66

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `human-judgement`
- **Remains for a person:** Compare several pages of the set (place on the screen, order in the code).

## Criterion 12.6

**Official title:** Les zones de regroupement de contenus présentes dans plusieurs pages web (zones d’[en-tête](glossary.md#zone-d-en-tete), de [navigation principale](glossary.md#menu-et-barre-de-navigation), de [contenu principal](glossary.md#zone-de-contenu-principal), de [pied de page](glossary.md#zone-de-pied-de-page) et de [moteur de recherche](glossary.md#moteur-de-recherche-interne-a-un-site-web)) peuvent-elles être atteintes ou évitées ?

### Tests

- **12.6.1** Dans chaque page web où elles sont présentes, la zone d’[en-tête](glossary.md#zone-d-en-tete), de [navigation principale](glossary.md#menu-et-barre-de-navigation), de [contenu principal](glossary.md#zone-de-contenu-principal), de [pied de page](glossary.md#zone-de-pied-de-page) et de [moteur de recherche](glossary.md#moteur-de-recherche-interne-a-un-site-web) respectent-elles au moins une de ces conditions ?

  - La zone peut être masquée par le biais d’un bouton précédent directement la zone dans l’ordre du code source ;
  - La zone peut être évitée par le biais d’un [lien d’évitement](glossary.md#liens-d-evitement-ou-d-acces-rapide) précédent directement la zone dans l’ordre du code source ;

## Criterion 12.7

**Official title:** Dans chaque page web, un [lien d’évitement ou d’accès rapide](glossary.md#liens-d-evitement-ou-d-acces-rapide) à la [zone de contenu principal](glossary.md#zone-de-contenu-principal) est-il présent (hors cas particuliers) ?

### Tests

- **12.7.1** Dans chaque page web, un lien permet-il d’éviter la [zone de contenu principal](glossary.md#zone-de-contenu-principal) ou d’y accéder (hors cas particuliers) ?
- **12.7.2** Dans chaque ensemble de pages, le [lien d’évitement ou d’accès rapide](glossary.md#liens-d-evitement-ou-d-acces-rapide) à la [zone de contenu principal](glossary.md#zone-de-contenu-principal) vérifie-t-il ces conditions (hors cas particuliers) ?
  - Le lien est situé à la même place dans la présentation ;
  - Le lien se présente toujours dans le même ordre relatif dans le code source ;
  - Le lien est visible ou, à défaut, visible à la prise de focus ;
  - Le lien est fonctionnel.

### Special cases (cas particuliers)

Il existe une gestion de cas particuliers lorsque le site web est constitué d’une seule page.

Dans ce cas de figure, l’obligation de la présence d’un lien d’accès rapide est liée au contexte de la page : présence ou absence de navigation ou de contenus additionnels, par exemple. Le critère peut être considéré comme non applicable lorsqu’il est avéré qu’un lien d’accès rapide est inutile.

### WCAG references listed by the official file

- **Success criteria:** 2.4.1 Bypass Blocks (A); 2.4.3 Focus Order (A); 3.2.3 Consistent Navigation (AA)
- **Techniques:** G1, G59, G123, G124, SCR28, F66

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Code proves:** NC when there is no link to the main content, or on a link whose target does not exist (`href="#contenu"` without `id="contenu"`).
- **Remains for a person:** Check with the keyboard that the link is visible on focus and works, and that it keeps the same place across the set of pages.

## Criterion 12.11

**Official title:** Dans chaque page web, les contenus additionnels apparaissant au survol, à la prise de focus ou à l’activation d’un [composant d’interface](glossary.md#composant-d-interface) sont-ils si nécessaire atteignables au clavier ?

### Tests

- **12.11.1** Dans chaque page web, les contenus additionnels apparaissant au survol, à la prise de focus ou à l’activation d’un [composant d’interface](glossary.md#composant-d-interface) sont-ils si nécessaire atteignables au clavier ?

### Technical notes (notes techniques)

Ce critère adresse les situations où un contenu additionnel contient des [composants d’interface](glossary.md#composant-d-interface) avec lesquels il doit être possible d’interagir au clavier. Par exemple, une infobulle personnalisée qui propose un lien dans son contenu.

### WCAG references listed by the official file

- **Success criteria:** 2.1.1 Keyboard (A)
- **Techniques:** none listed

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Real-conditions check:** `keyboard`
- **Code proves:** NC on a submenu or a panel displayed only on hover (`mouseenter`, `:hover`) whose interactive content cannot be reached with the keyboard, or on a list opened on activation whose options are neither focusable nor reachable with the arrow keys (`<li>` or `<div>` with neither `tabindex` nor keyboard handling).
- **Remains for a person:** Check with the keyboard that each additional content, displayed on hover, on focus or on activation, is displayed and can be reached.
