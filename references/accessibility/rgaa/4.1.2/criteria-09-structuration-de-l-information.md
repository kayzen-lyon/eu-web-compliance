## Criterion 9.1

**Official title:** Dans chaque page web, l’information est-elle structurée par l’utilisation appropriée de [titres](glossary.md#titre) ?

### Tests

- **9.1.1** Dans chaque page web, la hiérarchie entre les [titres](glossary.md#titre) (balise `<hx>` ou balise possédant un attribut WAI-ARIA `role="heading"` associé à un attribut WAI-ARIA `aria-level`) est-elle pertinente ?
- **9.1.2** Dans chaque page web, le contenu de chaque [titre](glossary.md#titre) (balise `<hx>` ou balise possédant un attribut WAI-ARIA `role="heading"` associé à un attribut WAI-ARIA `aria-level`) est-il pertinent ?
- **9.1.3** Dans chaque page web, chaque passage de texte constituant un [titre](glossary.md#titre) est-il structuré à l’aide d’une balise `<hx>` ou d’une balise possédant un attribut WAI-ARIA `role="heading"` associé à un attribut WAI-ARIA `aria-level` ?

### Technical notes (notes techniques)

WAI-ARIA permet de définir des titres via le rôle `heading` et l’attribut `aria-level` (indication du niveau de titre). Bien qu’il soit préférable d’utiliser l’élément de titre natif en HTML `<hx>`, l’utilisation du rôle WAI-ARIA `heading` est compatible avec l’accessibilité.

### WCAG references listed by the official file

- **Success criteria:** 1.3.1 Info and Relationships (A); 2.4.1 Bypass Blocks (A); 2.4.6 Headings and Labels (AA); 4.1.2 Name, Role, Value (A)
- **Techniques:** G115, G130, H42, G141, ARIA4, ARIA12

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Code proves:** NC on a skipped level, an empty heading, or a passage styled as a heading with neither an `<hx>` tag nor `role="heading"`.
- **Remains for a person:** Judge, with the page in view, that each heading describes its section and that each visual heading is marked up.

## Criterion 9.2

**Official title:** Dans chaque page web, la [structure du document](glossary.md#structure-du-document) est-elle cohérente (hors cas particuliers) ?

### Tests

- **9.2.1** Dans chaque page web, la [structure du document](glossary.md#structure-du-document) vérifie-t-elle ces conditions (hors cas particuliers) ?
  - La [zone d’en-tête de la page](glossary.md#zone-d-en-tete) est structurée via une balise `<header>` ;
  - Les [zones de navigation principales et secondaires](glossary.md#menu-et-barre-de-navigation) sont structurées via une balise `<nav>` ;
  - La balise `<nav>` est réservée à la structuration des [zones de navigation principales et secondaires](glossary.md#menu-et-barre-de-navigation) ;
  - La [zone de contenu principal](glossary.md#zone-de-contenu-principal) est structurée via une balise `<main>` ;
  - La [structure du document](glossary.md#structure-du-document) utilise une balise `<main>` visible unique ;
  - La [zone de pied de page](glossary.md#zone-de-pied-de-page) est structurée via une balise `<footer>`.

### Special cases (cas particuliers)

Lorsque le doctype déclaré dans la page n’est pas le doctype HTML5, ce critère est non applicable.

### Technical notes (notes techniques)

La balise `<main>` peut être utilisée plusieurs fois dans le même document HTML. Néanmoins, il ne peut y avoir en permanence qu’une seule balise visible et lisible par les technologies d’assistances, les autres devant disposer d’un attribut `hidden` ou d’un style permettant de les masquer aux technologies d’assistances. À noter cependant que l’utilisation d’un style seul restera insuffisante pour assurer l’unicité d’une balise `<main>` visible en cas de désactivation des feuilles de styles.

- **Techniques:** G115, ARIA11

## Criterion 9.3

**Official title:** Dans chaque page web, chaque [liste](glossary.md#listes) est-elle correctement structurée ?

### Tests

- **9.3.1** Dans chaque page web, les informations regroupées visuellement sous forme de [liste](glossary.md#listes) non ordonnée vérifient-elles une de ces conditions ?
  - La liste utilise les balises HTML `<ul>` et `<li>` ;
  - La liste utilise les attributs WAI-ARIA `role="list"` et `role="listitem"`.
- **9.3.2** Dans chaque page web, les informations regroupées visuellement sous forme de [liste](glossary.md#listes) ordonnée vérifient-elles une de ces conditions ?
  - La liste utilise les balises HTML `<ol>` et `<li>` ;
  - La liste utilise les attributs WAI-ARIA `role="list"` et `role="listitem"`.
- **9.3.3** Dans chaque page web, les informations regroupées sous forme de [liste](glossary.md#listes) de description utilisent-elles les balises `<dl>` et `<dt>/<dd>` ?

### Technical notes (notes techniques)

Les attributs WAI-ARIA `role="list"` et `role="listitem"` peuvent nécessiter l’utilisation des attributs WAI-ARIA `aria-setsize` et `aria-posinset` dans le cas où l’ensemble de la liste n’est pas disponible via le DOM généré au moment de la consultation.

Les attributs WAI-ARIA `role="tree"`, `role="tablist"`, `role="menu"`, `role="combobox"` et `role="listbox"` ne sont pas équivalents à une liste HTML `<ul>` ou `<ol>`.

### WCAG references listed by the official file

- **Success criteria:** 1.3.1 Info and Relationships (A)
- **Techniques:** G115, G153, H40, H48, F2

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Code proves:** NC on a sequence presented as a list without `<ul>`, `<ol>`, `<dl>` or the roles `list` and `listitem` (bullets or dashes typed as text, successive `<br>`), or a `<ul>` whose children are not `<li>`.
- **Remains for a person:** See the rendering to spot the content visually presented as a list. A list of options using `role="listbox"` and `role="option"` falls under 7.1.

## Criterion 9.4

**Official title:** Dans chaque page web, chaque citation est-elle correctement indiquée ?

### Tests

- **9.4.1** Dans chaque page web, chaque citation courte utilise-t-elle une balise `<q>` ?
- **9.4.2** Dans chaque page web, chaque bloc de citation utilise-t-il une balise `<blockquote>` ?

### WCAG references listed by the official file

- **Success criteria:** 1.3.1 Info and Relationships (A)
- **Techniques:** G115, H49, F2

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Code proves:** NC on a quotation written in the code without `<q>` or `<blockquote>`, or a `<blockquote>` used for indentation.
- **Remains for a person:** Spot the quotations of dynamic or editorial content.
