## Criterion 7.1

**Official title:** Chaque [script](glossary.md#script) est-il, si nécessaire, [compatible avec les technologies d’assistance](glossary.md#compatible-avec-les-technologies-d-assistance) ?

### Tests

- **7.1.1** Chaque [script](glossary.md#script) qui génère ou contrôle un [composant d’interface](glossary.md#composant-d-interface) vérifie-t-il, si nécessaire, une de ces conditions ?
  - Le [nom, le rôle, la valeur, le paramétrage et les changements d’états](glossary.md#le-nom-le-role-la-valeur-le-parametrage-et-les-changements-d-etats) sont accessibles aux technologies d’assistance via une API d’accessibilité ;
  - Un [composant d’interface](glossary.md#composant-d-interface) accessible permettant d’accéder aux mêmes fonctionnalités est présent dans la page ;
  - Une [alternative](glossary.md#alternative-a-script) accessible permet d’accéder aux mêmes fonctionnalités.
- **7.1.2** Chaque [script](glossary.md#script) qui génère ou contrôle un [composant d’interface](glossary.md#composant-d-interface) respecte-t-il une de ces conditions ?
  - Le [composant d’interface](glossary.md#composant-d-interface) est [correctement restitué](glossary.md#correctement-restitue-par-les-technologies-d-assistance) par les technologies d’assistance ;
  - Une [alternative](glossary.md#alternative-a-script) accessible permet d’accéder aux mêmes fonctionnalités.
- **7.1.3** Chaque [script](glossary.md#script) qui génère ou contrôle un [composant d’interface](glossary.md#composant-d-interface) vérifie-t-il ces conditions (hors cas particuliers) ?
  - Le composant possède un nom pertinent ;
  - Le nom accessible du composant contient au moins l’[intitulé visible](glossary.md#intitule-visible) ;
  - Le composant possède un rôle pertinent.

### Special cases (cas particuliers)

Il existe une gestion de cas particuliers pour le test 7.1.3 lorsque :

- La ponctuation et les lettres majuscules sont présentes dans le texte de l’intitulé visible : elles peuvent être ignorées dans le nom accessible sans porter à conséquence ;
- Le texte de l’intitulé visible sert de symbole : le texte ne doit pas être interprété littéralement au niveau du nom accessible. Le nom doit exprimer la fonction véhiculée par le symbole (par exemple, “B” au niveau d’un éditeur de texte aura pour nom accessible “Mettre en gras”, le signe “>” en fonction du contexte signifiera “Suivant” ou “Lancer la vidéo”). Le cas des symboles mathématiques fait cependant exception (voir la note ci-dessous).

Note : si l’étiquette visible représente une expression mathématique, les symboles mathématiques peuvent être repris littéralement pour servir d’étiquette au nom accessible (ex. : “A>B”). Il est laissé à l’utilisateur le soin d’opérer la correspondance entre l’expression et ce qu’il doit épeler compte tenu de la connaissance qu’il a du fonctionnement de son logiciel de saisie vocale (“A plus grand que B” ou “A supérieur à B”).

### Technical notes (notes techniques)

Le critère 7.1 implémente la notion de « compatible avec les technologies d’assistance » telle que définie par les WCAG, ainsi que le recours à WAI-ARIA pour rendre un composant ou une fonctionnalité accessible. Le bon usage de WAI-ARIA est vérifié via les tests 7.1.1, 7.1.2, 7.1.3.

Note importante : dans un environnement HTML5, beaucoup de composants peuvent nécessiter JavaScript pour fonctionner ; en conséquence la fourniture d’une alternative à un composant JavaScript qui ne pourrait pas être rendu accessible devra bénéficier d’une méthode spécifique au composant en cause, permettant de le remplacer par une alternative accessible (et de le réactiver). Cela signifie que la désactivation de JavaScript pour l’ensemble de la page ne sera pas acceptée comme une méthode valable, à moins qu’elle ne remette pas en cause l’utilisation des autres composants.

### WCAG references listed by the official file

- **Success criteria:** 2.5.3 Label in Name (A); 4.1.2 Name, Role, Value (A)
- **Techniques:** G10, G135, G136, F15, F19, F20, F42, F59, F79, ARIA4, ARIA5, ARIA18, ARIA19, SCR21

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Code proves:** NC on a scripted component with no consistent role or no name (clickable `<div>`, icon button without a name), or whose state is not exposed (`aria-expanded` missing on a button that shows or hides content).
- **Remains for a person:** Check with a screen reader how the component and its state changes are conveyed.

## Criterion 7.2

**Official title:** Pour chaque [script](glossary.md#script) ayant une [alternative](glossary.md#alternative-a-script), cette alternative est-elle pertinente ?

### Tests

- **7.2.1** Chaque [script](glossary.md#script) débutant par la balise `<script>` et ayant une [alternative](glossary.md#alternative-a-script) vérifie-t-il une de ces conditions ?
  - L’[alternative](glossary.md#alternative-a-script) entre `<noscript>` et `</noscript>` permet d’accéder à des contenus et des fonctionnalités similaires ;
  - La page affichée, lorsque JavaScript est désactivé, permet d’accéder à des contenus et des fonctionnalités similaires ;
  - La page alternative permet d’accéder à des contenus et des fonctionnalités similaires ;
  - Le langage de script côté serveur permet d’accéder à des contenus et des fonctionnalités similaires ;
  - L’alternative présente dans la page permet d’accéder à des contenus et des fonctionnalités similaires.
- **7.2.2** Chaque élément non textuel mis à jour par un [script](glossary.md#script) (dans la page, ou dans un [cadre](glossary.md#cadre)) et ayant une [alternative](glossary.md#alternative-a-script) vérifie-t-il ces conditions ?
  - L’alternative de l’élément non textuel est mise à jour ;
  - L’alternative mise à jour est pertinente.

### WCAG references listed by the official file

- **Success criteria:** 1.1.1 Non-text Content (A); 4.1.2 Name, Role, Value (A)
- **Techniques:** G136, F19, F20

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Code proves:** NC on an empty `<noscript>`.
- **Remains for a person:** Judge that the alternative gives access to the same content and to the same functionality; NA when the script has no alternative.

## Criterion 7.3

**Official title:** Chaque [script](glossary.md#script) est-il [contrôlable par le clavier et par tout dispositif de pointage](glossary.md#accessible-et-activable-par-le-clavier-et-tout-dispositif-de-pointage) (hors cas particuliers) ?

### Tests

- **7.3.1** Chaque élément possédant un gestionnaire d’événement contrôlé par un script vérifie-t-il une de ces conditions (hors cas particuliers) ?
  - L’élément est [accessible par le clavier et tout dispositif de pointage](glossary.md#accessible-et-activable-par-le-clavier-et-tout-dispositif-de-pointage) ;
  - Un élément [accessible par le clavier et tout dispositif de pointage](glossary.md#accessible-et-activable-par-le-clavier-et-tout-dispositif-de-pointage) permettant de réaliser la même action est présent dans la page.
- **7.3.2** Un [script](glossary.md#script) ne doit pas supprimer le focus d’un élément qui le reçoit. Cette règle est-elle respectée (hors cas particuliers) ?

### Special cases (cas particuliers)

Il existe une gestion de cas particuliers lorsque la fonctionnalité dépend de l’utilisation d’un gestionnaire d’événement sans équivalent universel ; par exemple, une application de dessin à main levée ne pourra pas être rendue contrôlable au clavier. Dans ces situations, le critère est non applicable.

### WCAG references listed by the official file

- **Success criteria:** 1.3.1 Info and Relationships (A); 2.1.1 Keyboard (A); 2.4.7 Focus Visible (AA)
- **Techniques:** G90, G202, F42, F54, F55, SCR2, SCR20, SCR29, SCR35

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Real-conditions check:** `keyboard`
- **Code proves:** NC on an event handler placed on a non-focusable element (clickable `<div>` with neither `tabindex` nor handling of Enter, unless another keyboard-accessible element performs the same action), on a mouse handler with no keyboard equivalent, or on a script that removes focus (`blur()`).
- **Remains for a person:** Go through each scripted element with the keyboard (Tab, Enter, Space, arrow keys, Escape) and with the pointer; in component mode, also check that the component can be left with the keyboard (12.9).

## Criterion 7.4

**Official title:** Pour chaque [script](glossary.md#script) qui initie un [changement de contexte](glossary.md#changement-de-contexte), l’utilisateur est-il averti ou en a-t-il le contrôle ?

### Tests

- **7.4.1** Chaque [script](glossary.md#script) qui initie un [changement de contexte](glossary.md#changement-de-contexte) vérifie-t-il une de ces conditions ?
  - L’utilisateur est averti par un texte de l’action du script et du type de changement avant son déclenchement ;
  - Le changement de contexte est initié par un bouton (input de type `submit`, `button` ou `image` ou balise `<button>`) explicite ;
  - Le changement de contexte est initié par un lien explicite.

### WCAG references listed by the official file

- **Success criteria:** 3.2.1 On Focus (A); 3.2.2 On Input (A)
- **Techniques:** G13, G76, G80, G107, H32, H84, F9, F22, F36, F37, F41, SCR19

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Code proves:** NC on a change of context triggered with no explicit button or link and no text that announces it (`onchange` of a `<select>` that navigates or submits, move of focus that was not requested). The visible label of the triggering element counts as text when it names the action and its object ("Envoyer la demande de subvention", "Envoyer la demande n° 1234", that is "Send the grant application", "Send application no. 1234"); a verb alone ("Envoyer", "Valider", that is "Send", "Confirm") or a vague label ("OK", "→") does not count: NC. Only the visible label counts: a more explicit `aria-label` ("Envoyer la demande de subvention" on a button labelled "Envoyer") does not make up for a vague visible label. This ruling is stricter than the glossary, which includes `aria-label` in the label of the button: 7.4 first protects the person who sees the button.
- **Remains for a person:** Check in the browser that no script outside the audited code changes the context (automatic submission, partial reload).

## Criterion 7.5

**Official title:** Dans chaque page web, les [messages de statut](glossary.md#message-de-statut) sont-ils correctement restitués par les technologies d’assistance ?

### Tests

- **7.5.1** Chaque [message de statut](glossary.md#message-de-statut) qui informe de la réussite, du résultat d’une action ou bien de l’état d’une application utilise-t-il l’attribut WAI-ARIA `role="status"` ?
- **7.5.2** Chaque [message de statut](glossary.md#message-de-statut) qui présente une suggestion, ou avertit de l’existence d’une erreur utilise-t-il l’attribut WAI-ARIA `role="alert"` ?
- **7.5.3** Chaque [message de statut](glossary.md#message-de-statut) qui indique la progression d’un processus utilise-t-il l’un des attributs WAI-ARIA `role="log"`, `role="progressbar"` ou `role="status"` ?

### Technical notes (notes techniques)

Les rôles WAI-ARIA `log`, `status` et `alert` ont implicitement une valeur d’attribut WAI-ARIA `aria-live` et `aria-atomic`. On pourra donc considérer (conformément à la spécification WAI-ARIA 1.1) que :

- Un attribut WAI-ARIA `aria-live="polite"` associé à un message de statut peut valoir pour un rôle WAI-ARIA `log` ;
- Un attribut WAI-ARIA `aria-live="polite"` et un attribut WAI-ARIA `aria-atomic="true"` associés à un message de statut peuvent valoir pour un rôle WAI-ARIA `status` ;
- Un attribut WAI-ARIA `aria-live="assertive"` et un attribut WAI-ARIA `aria-atomic="true"` associés à un message de statut peuvent valoir pour un rôle WAI-ARIA `alert`.

C’est sous réserve que la nature du message de statut satisfasse bien à la correspondance implicitement établie. Dans le cas d’un message de statut indiquant la progression d’un processus et matérialisé graphiquement par une barre de progression, un rôle WAI-ARIA `progressbar` explicite est nécessaire.

### WCAG references listed by the official file

- **Success criteria:** 4.1.3 Status Messages (AA)
- **Techniques:** ARIA19, ARIA22, ARIA23

### Evaluation mode (provisional, not part of the RGAA)

- **Mode:** `mixed`
- **Code proves:** NC on a success, error or progress message inserted without `role="status"`, `role="alert"`, `role="log"` or `role="progressbar"`, and without their equivalents allowed by the technical notes (`aria-live="polite"` or `aria-live="assertive"` with `aria-atomic="true"`).
- **Remains for a person:** Spot in the browser the messages added by scripts outside the audited code, and check with a screen reader that they are announced.
