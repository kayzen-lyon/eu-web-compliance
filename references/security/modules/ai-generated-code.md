# Module: AI-generated code

This module applies to every project where an AI assistant writes code, which includes the work you are doing with this skill. It follows section 5.5 of the ANSSI guide on generative AI systems (ANSSI-PA-102; version and date in [../../regulatory-status.md](../../regulatory-status.md) section 4), recommendations R30 to R32.

## How to use this file

1. Read it once per project, before writing code, and again before writing the final report.
2. The ANSSI guide addresses the organisation that uses an AI assistant. Rules that only a person can carry out are phrased as what you must tell that person; the rest you apply yourself.
3. Tags: `ANSSI AI` is ANSSI-PA-102; other tags as in [../web-baseline.md](../web-baseline.md).

## Why it matters

The guide warns that AI-generated code can introduce vulnerabilities and, if the model were compromised, a backdoor. Generated code tends to look plausible and complete, which makes its defects easy to miss in review. Typical defects on websites: string-built SQL, `innerHTML` with user data, permissive CORS or CSP copied from a tutorial, invented package names, weak password hashing, access checks only in the user interface.

## 1. What you do while generating code

- [ ] Do not run generated code automatically in the developer's environment (install scripts, migrations, shell commands) without the person seeing and approving it [ANSSI AI R30]
- [ ] Do not commit or push generated code yourself unless the person asked for it in this session; leave the review and commit to them [ANSSI AI R30]
- [ ] Check every library or package you reference: it exists in the official registry under that exact name, it is the intended one, it is maintained [ANSSI AI R30]
- [ ] Run the project's linters, type checker, tests and security checks (`scripts/check-security.mjs` and the dependency audit) on what you generated, and report their output [ANSSI AI R30]
- [ ] Do not generate cryptographic code, authentication, session handling, access control or code that processes sensitive data from scratch; use the framework's or a maintained library's implementation and configure it [ANSSI AI R31]
- [ ] Take numeric security values only from [../anssi-values.md](../anssi-values.md), never from memory [best practice]

ANSSI R31 lists the critical modules: cryptography (authentication, encryption, signature), management of user and administrator access rights, and processing of sensitive data. On a website that means: sign-in and sign-up, password storage and reset, sessions and tokens, roles and permissions, payment integration, and handlers of health, identity or financial data.

## 2. What you tell the person in the final report

- [ ] List the files you created or changed, and mark those in the critical modules above as "needs human review before going live" [ANSSI AI R31]
- [ ] State that the code was generated by an AI and must be reviewed by a person before it is committed and deployed [ANSSI AI R30]
- [ ] Recommend a code-cleaning or static analysis tool in the editor or CI if the project has none [ANSSI AI R30]
- [ ] Suggest that a person periodically reviews the quality of generated code, using demanding sample requests [ANSSI AI R30]
- [ ] Suggest that the team is made aware of the risks of AI-generated code [ANSSI AI R32]

## 3. Review checklist for generated web code

Use it on your own output before reporting, and on code another assistant produced.

- [ ] No secret, key or password in the code or in front-end bundles [OWASP A07]
- [ ] Server-side validation for every input, parameterised queries, no `eval` [ANSSI WEB R8, R9]
- [ ] Output escaping left on in templates; no `innerHTML` or `dangerouslySetInnerHTML` with data that is not sanitised [ANSSI WEB R4, R7]
- [ ] Authorisation checked on the server for each object [OWASP A01]
- [ ] CSP and CORS not loosened to make an error disappear [ANSSI WEB R15, R40]
- [ ] Errors caught without exposing details, and failures that deny rather than allow [OWASP A10]
- [ ] Dependencies added are pinned in the lock file and pass the audit [OWASP A03]
