# Trackers: inventory, exemptions, what may run before consent

What counts as a tracker, how to find every tracker in a codebase, which ones may run without consent and under what conditions, and how to hold the others back until the visitor agrees.

## How to use this file

1. Read section 1 to know what you are looking for, then run the inventory of section 2 on the repository before you add or change anything that loads a script, an iframe, a font, a pixel or an SDK.
2. Classify each finding with section 3 (exempt or not). When a tracker does not fit an exemption **exactly**, it waits for consent. Doubt means consent.
3. Apply section 4 when you write the page: nothing that needs consent may run, be requested or be stored before the choice.
4. Build the consent interface with [consent.md](consent.md) and the reference banner in [../../templates/consent/README.md](../../templates/consent/README.md). Write the cookie policy with [../../templates/cookie-policy.md](../../templates/cookie-policy.md).
5. A line starting with `- [ ]` is a rule; its source is in square brackets at the end. `ePrivacy` and `GDPR` are EU law and apply in every Member State. `LIL` is French law. `CNIL ...` tags are the French regulator's reading or recommendations: they bind nobody outside France, and a site that targets another Member State needs that country's authority checked for the same points. `[best practice]` has no official source and is never an obligation.
6. Durations, dates and thresholds are not written here. They are in [../regulatory-status.md](../regulatory-status.md), section 3, which says which ones are required and which ones are only recommended.

Why this matters: the rule is about the visitor's device, not about personal data. Writing or reading anything on it without a valid reason is unlawful even if no name is ever known. Getting it wrong exposes the site owner to sanctions; refusing a harmless technical cookie by mistake only costs a little convenience. When unsure, block.

| Task | Read |
|------|------|
| Adding analytics, a pixel, a chat, a video, a map, a font or any third-party script | Sections 1 to 4 |
| Checking a site before release | Section 2, then section 5 |
| Measuring audience without a banner | Section 3.3 |
| Session replay or heatmap tools | Section 3.4 and [consent.md](consent.md) section 8 |
| Tracking pixels in emails sent by the site | [consent.md](consent.md) section 9 |

## 1. What counts as a tracker

The rule (Article 5(3) of the ePrivacy Directive; Article 82 of loi n° 78-17 in France) covers **any storing of information, or access to information already stored, in the terminal equipment** of a user. It applies whether or not the information is personal data.

- [ ] Treat as a tracker every read or write on the visitor's device, whatever the technology: HTTP cookies, `localStorage`, `sessionStorage`, IndexedDB, Cache Storage written by a third party, device fingerprinting, identifiers generated by the operating system or hardware [ePrivacy art. 5(3); CNIL guidelines § 13]
- [ ] Apply the rule even when the information stored or read is not personal data (a random identifier, a counter, a flag) [ePrivacy art. 5(3); CNIL guidelines § 14]
- [ ] Treat fingerprinting (computing an identifier from canvas, fonts, audio, screen or browser properties) as a tracker: it reads information from the device even though nothing is stored [CNIL guidelines § 13]
- [ ] Treat a pixel, beacon or tracking link that makes the device send an identifier or parameters to a server as a tracker [CNIL pixels § 2.1]
- [ ] Treat embedded third-party content as a tracker source when the provider sets or reads identifiers through it: video players, maps, social buttons and feeds, comment widgets, chat widgets, advertising, A/B testing, tag managers [CNIL FAQ embedded content]
- [ ] Count trackers set by third parties through the site as the site's responsibility: the publisher who lets a partner drop trackers must make sure consent is collected for them [CNIL guidelines § 35-36]

Things that are **not** trackers in themselves, but still matter:

- A request to a third-party server (a web font, a CDN library, an image) that stores and reads nothing on the device is not covered by Article 5(3). It does send the visitor's IP address to that third party, which is a transfer of personal data under the GDPR: handle it with [third-parties-and-transfers.md](third-parties-and-transfers.md). Many such services also set cookies; check, do not assume.
- Server logs are not trackers. They are personal data processing under the GDPR; see [forms-and-minimisation.md](forms-and-minimisation.md), section 7.

## 2. Inventory: find every tracker in the codebase

Run this before writing the consent configuration. A banner is only as good as the inventory behind it: a script you did not find is a script that runs without consent.

### 2.1 Static search

Search the source, templates, build configuration and dependencies. The patterns below are **illustrations** of what to look for, not a closed list; vendors change hosts and names.

| What to search | Illustrative patterns |
|----------------|----------------------|
| Script and iframe tags pointing outside the site | `<script src="https://`, `<iframe src="https://`, `<img src="https://` with width or height 1, `<link rel="preconnect"` |
| Analytics and tag managers | hosts such as `googletagmanager.com`, `google-analytics.com`, `matomo` or `piwik`, `plausible`, `clarity.ms`, `hotjar`, `segment`, `mixpanel`, `amplitude`, `posthog`, `/collect`, `gtag(`, `_paq.push`, `dataLayer` |
| Advertising and social pixels | `fbq(`, `connect.facebook.net`, `snap.licdn.com`, `ttq.`, `doubleclick`, `adservice`, `criteo`, `taboola`, `outbrain` |
| Embeds | `youtube.com/embed`, `player.vimeo.com`, `maps.google`, `google.com/maps`, `openstreetmap` tiles from third-party hosts, `platform.twitter.com`, `instagram.com/embed`, `disqus` |
| Chat, support, session replay | `intercom`, `crisp`, `zendesk`, `tawk`, `drift`, `livechat`, `fullstory`, `logrocket`, `smartlook`, `contentsquare`, `mouseflow` |
| Fonts and CDNs | `fonts.googleapis.com`, `fonts.gstatic.com`, `use.typekit.net`, `cdn.jsdelivr.net`, `unpkg.com`, `cdnjs.cloudflare.com` |
| Anti-bot and payment | `recaptcha`, `hcaptcha`, `turnstile`, `js.stripe.com`, `paypal.com/sdk` |
| Packages in `package.json`, `composer.json`, `Gemfile`, plugin lists | names containing `analytics`, `gtag`, `gtm`, `pixel`, `tracking`, `segment`, `sentry`, `datadog`, `hotjar`, `intercom`, `react-ga`, `vue-gtag`, `@next/third-parties` |
| First-party code that stores on the device | `document.cookie`, `localStorage.`, `sessionStorage.`, `indexedDB.open`, `caches.open`, `navigator.sendBeacon`, `Set-Cookie` in server code, cookie helpers of the framework |
| Fingerprinting signals | `canvas.toDataURL` or `getImageData` outside drawing code, `AudioContext` used without sound, enumeration of `navigator.plugins`, `fonts`, `hardwareConcurrency`, `deviceMemory` combined into a hash |
| CMS and site builders | analytics or marketing plugins in WordPress, Shopify apps, settings that inject "tracking code" or "custom head scripts" |

For each finding, record: what it is, who operates it (the site or which third party), what it stores or reads (names of cookies and keys), its purpose, and whether it sends data outside the EU. That record feeds the cookie policy and the consent configuration.

- [ ] Keep the inventory as a file in the repository (for example `compliance/trackers.json` or a table in the cookie policy source), one entry per tracker, with operator, purpose, names stored, lifetime and exemption claimed or consent purpose [best practice]
- [ ] Ask the site owner about anything the code cannot show: tags added through a tag manager interface, scripts injected by the hosting platform or a CMS plugin, email pixels added by the newsletter tool [best practice]

### 2.2 Runtime check

The static search misses what tag managers and SDKs load at run time. Confirm in a browser:

1. Open the page in a fresh profile (no stored cookies), do not interact with the banner.
2. List the cookies, `localStorage`, `sessionStorage` and IndexedDB entries present, and every request to a host other than the site's own.
3. Repeat after "Refuse all", then after "Accept all", on several page types (home, a page with an embed, a form, checkout).

Before any choice and after refusal, the only entries allowed are exempt ones (section 3), and the only third-party requests allowed are those that store or read nothing and are covered for the GDPR (section 1). Section 5 lists the checks.

## 3. Exemptions and their strict conditions

### 3.1 The two exemptions in the law (EU baseline)

Consent is not needed for storage or access that is either:

- for the **sole purpose of carrying out the transmission** of a communication over a network; or
- **strictly necessary** to provide an information society service **explicitly requested** by the user.

- [ ] Claim an exemption only when the tracker is used **exclusively** for an exempt purpose; one tracker serving an exempt purpose and another purpose needs consent [ePrivacy art. 5(3); CNIL guidelines § 47-48]
- [ ] Judge "strictly necessary" from the visitor's point of view: without it, the feature the visitor asked for would not work. Being useful to the business (statistics for marketing, advertising revenue) does not make a tracker necessary [ePrivacy art. 5(3)]
- [ ] Use a separate tracker for each purpose, so that refusing one purpose never disables a tracker the site needs to work [CNIL recommendation § 6]

### 3.2 Trackers the CNIL regards as exempt (France)

The CNIL lists the following as able to be exempt, **in the state of the practices it knows**; the list is not exhaustive and each case still has to meet section 3.1. Other authorities hold similar but not identical positions: check them for other Member States.

- [ ] A tracker that stores the visitor's choice about trackers (consent or refusal), and nothing else [CNIL guidelines § 49]
- [ ] Authentication trackers, including those that secure the authentication mechanism, for example by limiting robotic or unexpected access attempts [CNIL guidelines § 49]
- [ ] A tracker that keeps the content of a shopping basket, or that serves to bill the products or services bought [CNIL guidelines § 49]
- [ ] Interface personalisation the visitor expects as part of the service, such as the chosen language or display mode, when it is an intrinsic and expected element of the service [CNIL guidelines § 49]
- [ ] Load balancing [CNIL guidelines § 49]
- [ ] On a paid site, a tracker that limits free access to a sample of content requested by the visitor (a set quantity or period) [CNIL guidelines § 49]
- [ ] Some audience measurement trackers, only under the conditions of section 3.3 [CNIL guidelines § 49-51]

Cases that are **not** exempt and are often wrongly treated as such (illustrations, not a closed list):

- [ ] Affiliation trackers need consent [CNIL FAQ affiliation]
- [ ] An anti-fraud tracker is in general not exempt, except where it only secures authentication [CNIL FAQ fraud]
- [ ] A CAPTCHA may run without consent only if its sole purpose is security for the benefit of the user; if the provider also uses it for other purposes, it needs consent [CNIL FAQ CAPTCHA]
- [ ] Social sharing buttons and embedded third-party content need consent as soon as the provider stores or reads trackers for purposes other than the interaction the visitor asked for [CNIL FAQ social buttons]
- [ ] Invoking "legitimate interest" in a banner never authorises a non-exempt tracker to run without consent [CNIL FAQ legitimate interest]

The CNIL notes that the law does not require informing visitors about exempt trackers, and recommends doing so anyway, for example in the privacy or cookie policy.

- [ ] List exempt trackers and their purposes in the cookie policy [CNIL recommendation § 5]

### 3.3 Audience measurement without consent (France)

An analytics tool may run without consent only if **every** condition of the CNIL guidelines below holds (the first four rules). If one fails, it is a tracker that waits for consent like any other. The rules after them are CNIL recommendations: follow them, but a recommended duration is not a condition of the exemption ([../regulatory-status.md](../regulatory-status.md) section 3.3).

- [ ] Its purpose is strictly limited to measuring the audience of this site or app (performance, navigation problems, technical optimisation, server sizing, content consulted), for the exclusive account of the publisher [CNIL guidelines § 50-51]
- [ ] It does not allow tracking the person's navigation across other sites or apps [CNIL guidelines § 51]
- [ ] It only produces anonymous statistics [CNIL guidelines § 51]
- [ ] The personal data it collects are not cross-referenced with other processing and are not transmitted to third parties; a vendor that reuses the data for its own purposes breaks this condition [CNIL guidelines § 51]
- [ ] Recommended, not a condition of the exemption: the tracker's lifetime and the data retention follow the durations the CNIL recommends, listed in [../regulatory-status.md](../regulatory-status.md) section 3.3, and the lifetime is not extended automatically on each new visit [CNIL recommendation § 5]
- [ ] Visitors are informed of the measurement, for example in the privacy policy, and can object to it where the processing rests on legitimate interest [CNIL recommendation § 5; CNIL FAQ objection]
- [ ] Do not describe any tool as "exempt", "CNIL-approved" or "CNIL-compliant": the CNIL publishes no list of exempt tools (vendors only self-assess), and the outcome depends on the configuration [CNIL FAQ exempt tools]

What this means in code: whatever the product, the agent checks its configuration (IP truncation or anonymisation options, no user identifier, no cross-site cookies, no data sharing with the vendor, no advertising features, no linking with accounts), records which conditions are met and which cannot be verified from the code, and asks the owner to confirm the vendor contract. When the agent cannot confirm every condition, it puts the tool behind consent. The data processing itself remains subject to the GDPR, and transfers outside the EU are a separate question ([third-parties-and-transfers.md](third-parties-and-transfers.md)).

### 3.4 Session replay, heatmaps and similar tools (France)

Tools that record mouse movements, clicks, scrolls and page content to replay or aggregate sessions are not exempt.

- [ ] Session replay starts only after consent for that specific purpose [CNIL session replay]
- [ ] The rest of the CNIL recommendation (information, masking by default, exclusion of passwords and bank data, no advertising retargeting) is in [consent.md](consent.md) section 8 [CNIL session replay]

## 4. What may run before consent, and what must wait

The default state of every page, before the visitor has chosen and after a refusal, is: no non-exempt tracker stored, read or loaded.

- [ ] Before the choice, the page stores or reads only exempt trackers [ePrivacy art. 5(3); LIL art. 82]
- [ ] A script whose purpose needs consent is not executed before consent for that purpose: it is not just "disabled" after loading, it is not loaded. Declare it as inert (`<script type="text/plain" data-consent-purpose="...">`) or load it from code that runs only after consent [ePrivacy art. 5(3)]
- [ ] An iframe from a provider that sets or reads trackers is replaced by a placeholder until consent; the placeholder explains what loading it involves and offers a button to allow it [CNIL FAQ embedded content]
- [ ] Refusing, closing the banner or ignoring it leaves the site usable; only the content that depends on the refused purpose is replaced by its placeholder [CNIL FAQ embedded content]
- [ ] Silence, scrolling or continuing to browse is a refusal, never a consent: nothing that needs consent runs until a positive action [CNIL guidelines § 27; CNIL recommendation § 2]
- [ ] A tag manager that itself sets or reads trackers, or that loads trackers, is loaded only after consent, or configured so that it loads nothing that needs consent before the choice; verify the result at run time, not in its settings [ePrivacy art. 5(3)]
- [ ] Prefer to hold back vendor "consent modes" that send cookieless pings before consent, unless you can show they neither store nor read anything on the device; their requests also carry the IP address to the vendor [best practice]
- [ ] After withdrawal, the site stops reading and writing the trackers concerned: it deletes its own cookies and storage entries for that purpose and stops the requests to the third parties concerned [CNIL FAQ withdrawal; CNIL recommendation § 3]

Exempt and needing nothing (no banner) is a valid design. A site that only uses exempt trackers does not need a consent banner, and the skill should not add one.

- [ ] When the inventory finds no tracker that needs consent, do not add a consent banner; mention exempt trackers in the cookie or privacy policy instead [CNIL recommendation § 5]

Ways to avoid needing consent at all (choices that respect visitors, to offer the owner, not obligations):

- Self-host fonts and libraries instead of loading them from a third-party CDN [best practice]
- Link to a video or map rather than embedding it, or use a placeholder that loads the embed only on request [best practice]
- Use a server-side or exemption-compatible audience measurement configuration and check section 3.3 [best practice]
- Use share links (plain `<a href>` to the network's share URL) instead of the network's script buttons [best practice]

## 5. Automated check before release

Run in a fresh browser context, without accepting anything. Expected result on a compliant page:

- [ ] Before any choice: no cookie, storage entry or IndexedDB database other than exempt ones, and no request to a third-party host that sets or reads trackers [ePrivacy art. 5(3)]
- [ ] After "Refuse all": same state, plus the cookie or storage entry that records the refusal [ePrivacy art. 5(3); CNIL guidelines § 49]
- [ ] After "Accept all": the scripts of each accepted purpose run [best practice]
- [ ] After withdrawal through "Manage cookies": the cookies and entries of the withdrawn purpose are gone and its scripts no longer load on the next page [CNIL FAQ withdrawal]
- [ ] Report anything the browser cannot prove (what a third party does on its servers, whether the analytics vendor reuses data) as "not tested", never as compliant [best practice]

The reference banner's README describes such a test with Playwright: [../../templates/consent/README.md](../../templates/consent/README.md).

The skill automates these checks, from the root of the website project: `node <skill>/scripts/check-privacy.mjs <folder or URL> --trackers compliance/trackers.json` (or `check-all.mjs`, which passes the project's `compliance/trackers.json` itself; see `SKILL.md`, "Paths"). It cannot read a tracker's purpose from its name, so the site declares its exempt trackers in `compliance/trackers.json`; anything set before consent that is not declared there is reported as a non-conformity, and a name that only suggests an exempt purpose is reported "to review". Start from [../../templates/trackers.example.json](../../templates/trackers.example.json), which already declares the `eu-consent` cookie of the reference banner. Declaring a tracker as exempt is a claim the owner must be able to justify against section 3; the file does not make it true.
